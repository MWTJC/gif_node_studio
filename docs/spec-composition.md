# 规格合成语义（重要修正）

## 问题背景（已修复；画面裁剪节点已改为序列级，见[决策 #95](decisions/91-100.md#d95)）

「视频输入 → 画面裁剪 → 画面裁剪 → 格式化」时：
- 第二个裁剪的**预览**正确（基于第一个裁剪的预览图，数据级累积）；
- 但**格式化输出**只有第二个裁剪生效——因为裁剪节点把 `manifest.crop` **替换**成自身规格，
  而解码只应用清单里的一份规格。

## 修复原则

**凡在清单上携带归一化规格的变换节点，链式时必须与上游规格“合成”，而不是“替换”**，
否则预览（数据级累积）与解码（对原始源应用单份规格）必然分叉。

- ~~`CropNode`（清单级，已删除）~~：`effective = manifest.crop.compose(own)`，写入
  `manifest.crop`；预览应用 `own`（叠加在已裁剪的预览图上），两者结果一致。
  **现状**：画面裁剪节点已改为序列级（`sequence_crop`，序列→序列，`backend.crop_sequence`
  逐帧直接裁剪），不再写 `manifest.crop`——`manifest.crop` 与 `CropSpec.compose` 保留在
  数据模型中，仅为旧存档携带的裁剪值在格式化解码时继续生效（无节点写入，恒为恒等
  (0,0,1,1)）。
- `TimeTrimNode` / `FrameTrimNode`：参数为「**slider 起点百分比** + **数值持续时长**」
  （时间截取=持续秒数 float，帧位截取=持续帧数 int，数值参数 `widget="spin"`（FloatParam/IntParam）生成纯数值框）；
  执行时 `start = 起点% × 源总时长/总帧数`、`end = start + 持续`；**全部规格叠加生效**。
- **截取串行合成（`compose_trim`，与 `CropSpec.compose` 同语义）**：每个截取节点的
  「开始 %」是**相对前级截取窗口**的长度百分比，`duration` 是相对该窗口的持续长度
  （秒 / 帧数）——后级基于前级的结果进一步截取（如多个画面裁剪节点叠加实现更精细的
  裁剪），**不是取交集**。合成结果为**源坐标系**的单份绝对窗口，覆写
  `(range_mode, start, end)`：
  - 上游未截取（`start`/`end` 均为 `None`）：以源全长为窗口（首个截取节点行为不变）；
  - 同模式：`start = 上游起点 + 百分比 × 上游长度`，`end = start + duration`；
  - 跨模式（time↔frame，仅视频）：按 `fps ≈ 总帧数/总时长` 换算窗口边界后同样串行合成，
    帧窗口取「上游窗口内首帧 + 百分比 × 窗口帧数」，时间窗口取「上游窗口起始秒 + 百分比 × 窗口秒数」；
  - **窗口钳制（用户需求修正）**：后级最多只能处理前级交给它的窗口——合成结果的
    `end` 按上游窗口终点钳制（`min(end, 上游窗口终点)`），因此
    「帧位截取1(50%,30帧) → 帧位截取2(0%,50帧)」的结果是前级的 30 帧，
    而非按源坐标系外扩的 50 帧（修复前格式化产物为 50 帧）；
  - 窗口为空（长度 ≤ 0）或缺少探测数据时抛出清晰中文错误；
  - 后级结果不再超出源末尾（各层窗口均被钳制到上游边界，最上游以源为界）。
  同一节点重复运行只会用当前参数重新合成（其输入是上游清单的合成窗口，不含自身旧结果）。

## 验证

- 两次右半裁剪（40×20 源）：预览 10×20、`manifest.crop.right == 0.25`、格式化产物 10×20 —— 三者一致。
- 跨模式截取（2s@10fps 视频）：时间截取 [0.5s, 2.0s] → 帧位截取 40%+2 帧 → 帧窗口
  [11, 13)（相对时间窗帧 5..19 取 40% 起点 = 帧 11）、格式化产物恰 2 帧（后级基于前级结果进一步截取）。
- 窗口钳制（100 帧静态序列）：帧位截取 50%+30 帧 → 帧位截取 0%+50 帧 → 合成窗口
  [50, 80)（终点 100 被钳制到前级终点 80）、格式化产物恰 30 帧（而非 50 帧）。
- 回归测试：`test_chained_crops_compose_in_manifest`、`test_same_mode_trims_compose`、
  `test_cross_mode_trims_compose_on_video`、`test_cross_mode_trims_reverse_order_composes`、
  `test_trim_chain_uses_relative_percent`、`test_frame_trim_chain_clamped_to_upstream_window`。
