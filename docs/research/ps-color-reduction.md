## 1. 背景与目标

用户希望在节点式工作流（anime-gif-node-studio）中实现 PS「存储为 Web 所用格式」
对 GIF 的颜色深度控制，包含两组参数：

- **减低颜色深度算法**：随样性(Perceptual) / 可感知(Adaptive) / 可选择(Selective) /
  受限(Web) / 黑白 / 灰度 / Windows / Mac OS；
- **仿色算法**：图案 / 扩散 / 杂色 / 无仿色。

已落地并**保留**的成果（方案 A，非本次实验）：

- 「仿色节点」重构为「颜色深度」节点（kind=`dither`，`DitherNode`）：
  - `algorithm` 下拉：可感知(自适应)/随样性(感知)/受限(Web)/灰度/黑白/Windows/Mac OS
    （**「可选择 Selective」为 Adobe 私有算法，按用户指示不实现**）；
  - `colors`（颜色数 2–256）、`dither` 下拉（扩散/无仿色/图案/杂色）、
    `map`（图案阈值图，官方 19 + 自定义）、`levels`（均匀色阶）；
  - `web_safe` 独立勾选移除，由「受限(Web)」算法承担；
  - Windows/Mac OS = remap 到 `data/palettes/*.png` 系统色板（256×1 RGB，
    用户可替换，缺失自愈生成）；
- 后端 `color_reduce_sequence`：逐帧预处理（灰度转换/有序仿色/加噪/固定色板
  remap）→ 共享 `MagickQuantizeImages` 量化（固定色板路径 remap 已就位）→ 导出 PNG；
- `_wand_quantize_all` 增加 `colorspace` 参数（adaptive=srgb、perceptual=lab）。

## 2. 实验一：调色板先行（PS 语义对齐）

### 2.1 动机

PS 中「减低颜色深度算法 + 颜色数」决定**调色板内容**，仿色算法只决定**像素如何
分配到调色板**（调色板与仿色无关）。初版实现中「图案/杂色」在量化**之前**改写
像素（先有序仿色/加噪），导致调色板随仿色变化，与 PS 不符。

### 2.2 实证

`MagickQuantizeImages` 生成的调色板与 dither 参数**无关**（no 与 floyd_steinberg
在 srgb/lab、treedepth 0/8 下逐一相同）——「扩散 ↔ 无仿色」本就满足 PS 语义；
差异只来自图案/杂色的预处理位置。

### 2.3 实现（已回退）

`color_reduce_sequence` 改为两段式：

1. 从原始序列（仅灰度转换，不做仿色预处理）NoDither 量化一次得共享调色板，
   经 `_palette_blob_from_sequence`（整条序列 histogram 颜色并集）提取为
   affinity 图像；
2. 重新解码原始帧，按仿色算法做「分配」：图案/杂色先做像素预处理，再
   `remap` 到该固定调色板（扩散=floyd_steinberg，其余=no）。

四种仿色下调色板恒等（实测逐色一致），仅像素分配不同。代价：octree 路径帧
解码两次。

### 2.4 回退原因

- 对**小颜色数**（2–16）该语义与 PS 一致，效果良好；
- 但用户实测在**更多颜色参数**（如 128/256 色）时效果变差：affinity 提取
  经 histogram 并集 + 8bit 取整会损失精度；remap（最近色）替代
  `MagickQuantizeImages(dither=floyd_steinberg)` 的分配路径后，大调色板下的
  扩散仿色质量不如直接共享量化；且两段式多一次全帧解码。
- 结论：**「调色板先行」只对低颜色数有语义收益，大颜色数时整体劣化**，
  故整体回退到「逐帧预处理 + 共享量化」的初版实现。

## 3. 实验二：取色方式（频次中位切割，PS 近似）

### 3.1 动机

用户用 `seq_sample/取色_001.jpg`（1020×540）对比 PS 与颜色深度节点同参数输出，
调色板明显不一致：PS 可感知-4色 = 白/橙/亮蓝/暗蓝；本节点（octree）= 蓝/暗蓝灰/
灰/近白，**完全丢失橙色**。

### 3.2 图像色彩构成（实测）

| 色系 | 占比 | 中心位置 |
|---|---|---|
| 白（云） | 11.3% | (0.44, 0.70) |
| 蓝（左侧天空渐变） | 59.8% | (0.36, 0.44) |
| 暖色（橙/肤，右侧主体） | 19.1% | (0.79, 0.54) |

橙色为**小面积但视觉醒目**的高频色块（不在全图 8bit 量化 top-12 频率表内）。

### 3.3 本质差异：IM octree vs PS Adaptive

| | IM `MagickQuantizeImages`（octree） | PS Adaptive（私有） |
|---|---|---|
| 算法 | 颜色空间递归 8 等分建树，合并叶节点取**像素均值** | 从原图真实颜色按**频次 + 感知加权**挑选代表色 |
| 调色板 | 可产生原图不存在的「中间色」；小面积醒目色被均值稀释 | 保留原图真实出现的高频色（白/橙/双蓝） |
| 实测 4 色 | 蓝(4,83,162)/暗蓝灰(33,42,74)/灰(132,132,115)/近白(237,228,225) | 白(242,229,224)/橙(192,102,34)/亮蓝(26,150,217)/暗蓝(11,63,128) |

注：(33,42,74) 与 (132,132,115) 实测**不存在于原图**（叶均值产物）。

### 3.4 假设排除

- **中心加权**：暖色集中在右侧 (0.79,0.54) 而 PS 仍选中 → 中心加权非主因
  （Adobe 文档对 adaptive 的中心偏好记载亦不明确）；
- **贪心频次 + 最小间隔去重**：选出 白 + 3 蓝（蓝族占 60% 频次），PS 却选了
  2 蓝 + 橙 → 纯频次也不成立；
- **混合法**（高频固定 + 中位切割填充）：2/4 家族命中，比纯中位切割差。

### 3.5 实现（已回退）

- `_frame_histogram`：PIL `thumbnail(1024)` + `getcolors(1<<20)`（C 级速度，
  4K 图约 0.07s），16 级/通道量化桶（≤4096 桶）；极端噪声图回退 512px /
  PIL 中位切割 256 色；
- `_median_cut_palette`：Lab 感知空间经典中位切割——每次把权重最大且 Lab 跨度
  最宽的桶沿加权中位数对半切，桶色取 Lab 加权均值转回 sRGB；
- `color_reduce_sequence` 增加 `sampling` 参数（octree 默认 / median_cut），
  节点新增「取色方式」下拉。

### 3.6 实证结果（取色_001.jpg，可感知，无仿色）

| 取色方式 | 4 色调色板 | PS 家族命中 |
|---|---|---|
| octree | (4,83,162) (33,42,74) (132,132,115) (237,228,225) | 2/4 |
| 频次中位切割 | (12,66,147) (17,132,206) (137,144,157) (198,120,69) | **3/4** |

- 找回**橙色** (198,120,69)≈PS(192,102,34) 与**亮蓝** (17,132,206)≈PS(26,150,217)；
- 仅「白↔灰」未中：中位切割把白色云与浅蓝天均值成灰 (137,144,157)；
- 2 色同为肤/蓝家族但色值偏暗（肤 (167,135,122) vs PS (233,205,183)）。
- 尝试过的变体均未超过 3/4：step8 更细桶（同为 3/4）、众数代均值（1/4，丢
  暗蓝与纯橙）、贪心频次（白+3蓝）、中心加权（不变或变差）。

### 3.7 回退原因

- 用户实测：**更多颜色参数时表现更差**——16 级桶粒度（≤4096 桶）限制了大
  调色板的多样性；缩略图直方图对大 N 精度不足；中位切割对大 N 的桶均值色
  偏离 octree 的逐叶精化结果，整体观感劣于原共享量化；
- 且「取色方式」与「调色板先行」叠加后，两处都改变调色板生成路径，问题
  相互放大，难以归因。
- 结论：**PS 的 Adaptive/Selective 为 Adobe 私有算法，公开算法（octree /
  中位切割 / 频次贪心 / 中心加权 / 混合）均无法逐位复刻**；低颜色数下
  中位切割可显著逼近（3/4 家族），高颜色数下不如 octree。作为产品取舍，
  整体回退。

## 4. 关键结论（可复用）

1. **PS 调色板 = 减色算法 + 颜色数决定，仿色只做像素分配**（语义不变量）；
2. **IM `MagickQuantizeImages` 调色板与 dither 参数无关**（octree 树构建
   独立于分配），但 octree 叶均值会产生原图不存在的中间色、稀释小面积
   醒目色；
3. **PS Adaptive ≈ 频次 + 感知加权选色**，与 octree 误差最小化本质不同；
   公开算法中 **Lab 空间频次中位切割**是最接近的近似（低颜色数 3/4 家族）；
4. **中心加权假设不成立**（至少对本素材）；纯频次贪心亦不成立；
5. **调色板先行 / 中位切割均只在小颜色数（≤16 左右）有收益，大颜色数劣化**；
6. 精确复刻 PS 需要 Adobe 私有算法逆向（黑盒差分 + 大量样本拟合），超出
   当前产品范围。
7. **libimagequant/pngquant 已黑盒排除（2026-08 独立研究，非本文档实验）**：
   三轮黑盒差分（脚本+报告在 `ps-color-reduction-research` 独立仓库，
   不在仓库）实测 libimagequant（`pip install imagequant`，cffi 绑定）：
   4 色家族命中 0–2/4、64 色 10–12/64（中位 ΔE 39–51）——它优化的是感知质量
   （方差选盒 / 噪声区降权 / Voronoi 精化），选色逻辑与 PS 的频次语义系统性
   偏离，**不可作为 PS Adaptive/Perceptual 的替代**。Pillow 官方 wheel 的
   `Quantize.LIBIMAGEQUANT` 常量存在但编译时未启用（`check_feature('libimagequant')`
   为 False），需自编译或走发行版包，叠加 GPLv3+ 许可，不推荐引入。
8. **kmeans 家族是家族级对齐的理论最优（2026-08 黑盒结论）**：证据链 =
   Adobe 量化专利（直方图+分裂/聚类）＋ ImageReady/Dynamic Media/Substance 三处
   Adobe 产品实现 ＋ IM 官方维护者推荐（discussion #2365）＋ pngquant/ffmpeg/
   RgbQuant 三方「直方图/分裂初始化 + KMeans 精化」共识。落地候选：adaptive→
   IM `-kmeans`（内建、零新依赖；4K·256 色 >120s，需降采样）、perceptual→
   Lab 空间 kmeans（自实现或 sklearn）。这是「换算法」而非「换库」，详见
   REPORT.md §5.2 的五条落地建议。

## 5. 后续研究方向（候选）

- **混合取色**：小颜色数（≤16）用「频次中位切割」，大颜色数回退 octree 共享
  量化（自适应阈值）——避开两者各自最差区间；
- **调色板先行仅限低颜色数 + 扩散仿色**：保留语义收益，避免大 N 精度损失；
- **感知距离 remap**：分配阶段用 Lab 最近色替代 sRGB 最近色，缩小与 PS
  色差感知差异；
- **黑盒逆向 PS**：固定输入样本集（渐变/照片/插画 × 2..256 色 × 四算法 ×
  四仿色），解析 PS 输出的 GIF 颜色表，差分拟合选色权重（需人工采集大量
  PS 输出）。
- **黑盒差分扩展（已推进，2026-08）**：`ps-color-reduction-research` 独立仓库
  的三轮实验已给出家族级对齐结论（§4 第 7–8 条）：排除 libimagequant，锁定
  kmeans 家族；下一步可按 REPORT.md §5.2 落地「adaptive→IM `-kmeans` /
  perceptual→Lab kmeans」并复测 PS 家族命中率。
