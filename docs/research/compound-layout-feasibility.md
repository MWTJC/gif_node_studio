# 复合（分级）智能布局可行性分析 v2（2026-08，logo.json 实测）

> 结论先行：**可行，且已按用户语义实测收敛**。存在图类关系专用的自动排布
> 方法可引入——「分层布局（Sugiyama 家族）+ 复合图递归」是为「带嵌套分组的
> DAG」设计的标准解法（Graphviz dot 的 cluster 递归排秩、ELK Layered 的
> hierarchy handling 均为此范式）。针对 logo.json（60 节点 / 10 背景框 /
> **两组嵌套结构** / 59 边）的**终点锚定分级布局**原型实测：
>
> - **ico合成 的 7 项直连输入全部落在同一列**，列内次序 = 终点输入端口
>   定义顺序（256→128→…→16，与用户手排逐项一致）——「终点节点语义
>   明确性优先」已实现；
> - **背景板 = 输出端口并集节点**：组内无终点时以「有出边的成员」为锚，
>   组内流水线向右对齐到组的输出侧；
> - 全部硬约束通过：零重叠、零逃逸、59 条边全部左→右、嵌套保真
>   （嵌套框相对父框有 ~100px 可见内缩）、确定性；其余 4 个预设同样
>   零问题。
>
> 与已回退的 #108 本质区别：分组语义在布局中作为一等公民参与（组=超节点，
> 递归分级），**方向性由构造保证**而非后置平移补救；本次又按用户语义把
> **终点扇入**设为最高优先级分层锚。
>
> 遗留问题仅为**优雅度微调**（带的垂直次序与用户手排相反、列居中 vs
> 顶对齐），均有明确调优方向，不构成可行性障碍。

## 1. 背景与问题定义

### 1.1 现状（代码核实）

- `ui/hotkeys/hotkey_functions.py` 仅保留 NodeGraphQt 内建
  `auto_layout_nodes`（上游/下游自动布局），源码核实其机制：
  BFS 深度排名 → 同 rank 节点**无层内排序**地堆成单列 → 无交叉最小化、
  无节点尺寸参与、多连通分量混排、背景框仅布局后按原成员重包。
- #108 的智能布局已整体回退（`node.layout.smart`、`layout_graph_smart`、
  `_reposition_backdrops` 均不在代码中）；`core/graph_layout.py` 与
  `tests/test_graph_layout.py` 作为独立模块保留。
- 回退原因（用户实测，见 `docs/research/graph-layout-evaluation.md`）：
  ① 背景框防交叠的组块平移把**上游组块右移到下游右侧**；② 方形化/列拆分
  与 backdrop 分组语义冲突（同一逻辑阶段被拆散）。

### 1.2 本次需求（含用户新增语义）

1. 目标：`src/gif_node_studio/node_presets/logo.json`；
2. 正确处理**嵌套背景板**（logo.json 含 尺寸源⊂ico、背景框/背景框 1/
   背景框 2 ⊂ 透明图样源 两组嵌套）；
3. **分级处理**（按背景板层级逐级布局）；
4. 从左到右对应从起点到终点（方向硬约束）；
5. 无遮挡且优雅；
6. **（用户新增）终点节点的语义明确性优先级最高**：终点（如 ico合成，
   7 项输入）的直连输入必须算作同一级别语义——同列扇入，且列内次序按
   终点输入端口定义顺序；
7. **（用户新增）背景板可抽象为「具有子集内所有输出端口的一个节点」**：
   组提升为超节点时暴露成员出边并集，参与父级布局。

## 2. 方法调研：图类关系专用的自动排布

### 2.1 分层布局（Sugiyama 家族）

Sugiyama, Tagawa & Toda (1981) 框架：**分层 → 层内排序（交叉最小化）→
坐标分配**。工业实现：Graphviz dot（Gansner et al. 1993）、dagre、
ELK Layered、igraph `layout_with_sugiyama`。内建 `auto_layout_nodes` 只是
此家族的退化成员。本项目 `core/graph_layout.py` 已是该家族自研实现。

### 2.2 复合图（含嵌套分组）的分级布局

两大参考实现（网络查证）：
- **Graphviz dot**：*"The original ranking algorithm in dot is recursive on
  clusters"*（graphviz.org/docs/attrs/newrank）——排秩在 cluster 上递归；
- **ELK Layered**：`SEPARATE_CHILDREN` 为复合节点触发独立布局运行、
  `INCLUDE_CHILDREN` 单次运行包含子层级——即逐级组合的「分级处理」。
- **终点锚定分层**（本次新增，来自用户语义）：分层不从源点而从**终点**
  反向计算——终点的直连输入全部同层（扇入对齐）。这与 dot/ELK 的
  "priority layering" 思路一致（用户明确：终点语义 > 源侧语义）。

### 2.3 导入可行性

| 方案 | 可行性 | 理由 |
|---|---|---|
| ELK（Java）/ dagre（JS） | 不可行 | 违反进程内/零依赖约束 |
| Graphviz dot（二进制） | 勉强可行 | 可随包自编译但体积重、尺寸控制弱 |
| **自研复合布局（扩展现有 `core/graph_layout.py`）** | **可行** | 零依赖、纯计算可单测、组内复用已验证子模块；原型 v2 已实证 |

## 3. 核心设计 v2：终点锚定复合（分级）布局

### 3.1 分级分解（组树）

- 几何包含判定成员（与 NodeGraphQt `BackdropNode.nodes()` 的
  `Qt.ContainsItemShape` 同语义）；布局前必须快照成员。
- 节点归**最深**包含框；背景框按包含关系成树。
- logo.json 组树：ROOT → 输入源(3)、透明源(3)、像素化 1(8)、ico(9+
  嵌套尺寸源4)、gif(8)、透明图样源(3 嵌套框×5)。

### 3.2 终点锚定分层（用户语义 1）

```
每级布局（组内 / 根级）：
  anchors = 本层 EXPORT 成员 ∪ 含 EXPORT 的嵌套组
            （无则退化为「有组外出边的 item」= 组的输出端口）
  分层 = 反向最长路：dist(v) = v 到最近锚的最长距离
        layer(v) = D - dist(v)          # 锚在最右列 D
  [扇入钳制] 锚的直连输入强制 dist=1（同列）
         —— 仅当该输入的所有后继 dist≤1 时钳制（防方向反转）；
           同列边（A通道合并 2 → 分辨率统一 18）垂直呈现
  非核心节点（不达锚，如 ico分辨率查看）= 核心边界向后：
        layer = 最近核心祖先的层号 + 1     # 终点的侧输出靠右
```

- **效果**：ico合成 的 7 输入（含菱形结构 A通道合并 2 → 分辨率统一
  14/18/13/12）全部落在同一列；ico分辨率查看 在 ico合成 右侧一列；
  GIF 合成 同理由其终点锚定；根级三带（源→处理→汇）由「组=锚」自然产生。
- 方向性由构造保证：边 u→v 恒有 layer(u) ≤ layer(v)，无任何后置平移。

### 3.3 终点端口序扇入（用户语义 1 的次序）

- 终点的直连输入列内次序 = **终点输入端口定义顺序**
  （从节点类 `input_ports()` 提取；ico合成 = 256,128,64,48,32,24,16）；
- 在 barycenter 排序**之后**硬覆盖（终点语义优先级最高），非输入节点
  稳定保持原相对次序。

### 3.4 背景板 = 输出端口并集节点（用户语义 2）

- 组=超节点参与父级布局，出边 = 成员出边**并集**（owner 链逐级上提）；
- 组内无 EXPORT 时，以「有组外出边的成员」为伪锚 → 组内流水线向右
  对齐到组的输出侧（如 透明图样源 的 3 个嵌套框都是输出端口 → 同列堆叠，
  与用户手排一致）；
- 嵌套框相对父框内容区有内边距（含 `nest_inset`：含嵌套子框时
  pad_l≥100 / pad_t≥60，嵌套框四周可见父框底色——用户手排 ~106/50 基准）。

### 3.5 保护层

- 锚层 + 锚直连输入层为**保护层**：不参与方形化层合并、不参与列拆分
  （否则 7 输入列会被拆成多列，破坏「同一级别语义」）；
- 保护以节点 id 集传递（合并/拆分后索引漂移不可靠）。

### 3.6 与 #108 方案的本质差异

| 维度 | #108（已回退） | 本次 v2 |
|---|---|---|
| 背景框角色 | 布局后重包 + 组块平移避让 | 一等公民：组=超节点参与布局 |
| 方向保证 | 后置平移（可破坏） | 构造保证（分层单调） |
| 分层方向 | 源侧最长路 + 源就近下放 | **终点锚定反向最长路**（扇入优先） |
| 终点扇入 | 无 | 直连输入同列 + 端口序 + 保护层 |
| 嵌套背景板 | 不支持 | 递归分级 + nest_inset |
| 分组拆散 | 可拆散 | 组不可分 |

## 4. 原型实测（logo.json + 全部预设）

原型实测（临时脚本验证后已删除，算法已收敛落地为正式核心模块
`core/compound_layout.py`，实现方案见 [compound-layout-implementation-plan.md](compound-layout-implementation-plan.md)）：

### 4.1 数值断言（v2 对 logo.json）

| 指标 | 用户手排 | v2（正式核心模块实测） |
|---|---|---|
| 节点重叠 | 0（用户重排后已修） | **0** |
| 方向反（源左>目标左） | 0 | **0 / 59** |
| 成员逃出父框 | 0 | **0 / 50** |
| 嵌套框逃出父框 | 0 | **0 / 4** |
| 非成员落入嵌套框 | 0 | **0** |
| 兄弟背景框重叠 | 0 | **0** |
| ico合成 7 输入同列 | ✓（x≈2594-2680） | **✓（x=3090，单列）** |
| 7 输入列内次序 | 256→128→64→48→32→24→16 | **同左（端口序，逐项一致）** |
| 顶层组 x 序 | 透明源/输入源→透明图样源/像素化 1→gif/ico | 输入源/透明源→像素化 1/透明图样源→gif/ico |
| 分析节点位置 | 终点右侧同高 | 终点右侧一列（ico分辨率查看、图片1:1分辨率查看） |
| 确定性 | — | ✓（两次逐坐标一致） |
| 整体尺寸 | 4996×5635 | 4348×5642 |

### 4.2 平铺布局反证（为何必须分级）

对同一 logo.json 跑旧式**平铺**布局（全部节点一起、忽略背景框）：
**绝大多数组成员逃出其父背景框**——嵌套背景板在平铺算法下结构性失效，
分级是唯一可行路线。

### 4.3 边界情况（实测修正记录）

- **中游分叉的分析叶子**（如 序列GIF化 的 gif调色板查看 ← 颜色量化，
  不达锚）：不得落到最左列——非核心节点从「最近核心祖先」向后排
  （层 = 核心祖先层 + 1），方向保持；
- **菱形直连输入**（A通道合并 2 → 分辨率统一 18 → ico合成 且
  A通道合并 2 → ico合成）：最长路给深度 2，扇入钳制（后继全 ≤1 时
  强制 dist=1）→ 同列，列内垂直边；
- **核心传播不得跳过 indeg2 递减**（实测 bug：`continue` 使锚的 fwd
  传不到下游分析节点，全部落到层 0）；
- **嵌套框绝对坐标** = 父框绝对 + 父框内边距 + 父框内布局位置
  （漏父框 pad 会贴角；父框查找须用嵌套树而非「首个满足条件者」）。

### 4.4 渲染目检（offscreen 渲染 PNG + 目检）

- 嵌套框完整嵌于父框内、四周可见父框底色（nest_inset 生效）；
- 框无重叠、节点无一外泄；三带结构清晰（左输入 / 中处理 / 右汇出）；
- 最右汇框内 7 节点单列整齐扇入一个节点；
- 连线左→右方向感明确；整体紧凑。

## 5. 遗留的优雅度微调（不阻塞可行性）

1. **带的垂直次序与用户手排相反**：v2 把 输入源/像素化 1 放上、
   透明源/透明图样源 放下（barycenter 自洽的镜像）；用户手排反之。
   无语义差异，若要对齐用户偏好可加「带间对齐优先」（源带次序镜像
   消费带）或用户可接受算法自洽解。
2. **列垂直居中 vs 顶对齐**：v2 各列垂直居中（经典做法），列高差异大时
   呈阶梯感；用户手排近似「顶对齐 + 相邻贴靠」。可提供对齐模式参数。
3. **连线路由**：原型直线示意；真实应用由 NodeGraphQt 管道绘制，
   布局只需端点方向单调。

## 6. 落地建议（若进入实现，供方案审查）

- **模块**：`core/graph_layout.py` 增加复合入口 `layout_compound`
  （纯计算无 Qt），或新建 `core/compound_layout.py`；分层函数
  `_sink_anchored_layers` 与端口序/保护层参数作为可选能力。
- **锚定与端口序提取（UI 适配层）**：语义终点 = 注册表中含 `EXPORT_KIND`
  的节点类；端口序 = 节点实例 `input_ports()` 顺序（离屏提取，原型已验证）。
- **UI 接线**：恢复 `node.layout.smart`（Ctrl+Shift+L）；作用域「选中 ≥2
  布局选中、否则全图」；整体 `begin_undo("智能布局")` 单撤销宏；布局前
  `backdrop.nodes()` 快照成员、布局后按新尺寸 `set_property` 重设背景框。
- **测试契约**：现有 15 项 + 新增——嵌套两层的逃逸/包含、非成员不得落入
  嵌套框、**终点直连输入同列断言**、**端口序断言**、锚层/输入层不拆分、

- **验证流程**：纯计算断言 + offscreen 渲染 PNG 目检，**每改动必以
  logo.json 目检**（#108 教训：勿只信几何断言）。

## 7. 结论

1. **有无图类关系专用的自动排布方法可引入？有。** 分层布局（Sugiyama
   家族）是 DAG 排布的标准方法；对嵌套分组有专门的复合图分级布局范式
   （dot 递归 cluster / ELK hierarchy handling）；进程内自研可行、零依赖。
2. **嵌套背景板与分级处理：可行且已实测。** 后序递归正确处理 logo.json
   两组嵌套（含 3 路并列嵌套），全部数值断言通过。
3. **终点语义明确性优先：已按用户语义实现。** 终点直连输入同列扇入 +
   端口序定列内次序 + 保护层不拆散；分析节点作为终点侧输出靠右。
4. **背景板 = 输出端口并集节点：已实现。** 组内无终点时以输出端口成员
   为伪锚，流水线向右对齐到组输出侧。
5. **从左到右 = 起点到终点：构造保证。** 无任何后置平移，59/59 边通过。
6. **无遮挡：构造保证 + 实测 0 重叠 0 逃逸。**
7. **优雅：基本达成，余微调。** 渲染目检确认嵌套、三带、扇入、方向均
   清晰；带的垂直次序等为可调优审美项（§5）。

**建议**：以本分析为方案基础进入设计评审；若采纳，落地为新的决策记录，
并在实现后按 §6 验证流程回归。
