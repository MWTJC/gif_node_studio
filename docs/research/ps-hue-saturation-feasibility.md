# PS「色相/饱和度」选择性调色可行性调研（已落地：决策 #134）

> 需求来源：2026-09 用户提出——能否实现 PS「色相/饱和度」功能：**目标颜色可用
> 取色器指定**，核心是对**某种颜色**（而非全图）做色相、饱和度及明度调整。
> 本文档记录可行性调研与设计过程；**2026-09 已按本方案落地**（新增
> 「色相/饱和度」节点 + 删除「色相调整」+ 旧存档迁移），落地细节与验证见
> [决策 #134](../decisions/131-140.md#d134)。
>
> 关联先例：[决策 #129 颜色键](../decisions/121-130.md#d129)（同族「目标色 +
> 容差/羽化」的 numpy 向量化逐帧实现）；PS 对齐研究手法见
> `ps-color-reduction.md`（黑盒差分标定）。
>
> 最后更新：2026-09-05。

## 1. 结论速览

- **可行**。PS「色相/饱和度」对话框可复刻的核心 =
  「按**色相距离**生成权重蒙版（中心全量 + 过渡衰减）→ 对蒙版内像素做色相偏移 /
  饱和度 / 明度调整」，与项目已落地的 颜色键 `color_key_tolerance_sequence`
  （numpy 逐帧 + 8-worker `_parallel_pil_export`）是同一计算形态，性能与架构
  风险低。
- **目标色 = ColorParam 色块取色器**：等价于 PS 吸管「把中心色域移到所点颜色」。
  差异：PS 吸管在图像内点选并可加/减采样（色域可多段），本项目无画布级取色
  交互——用「取色器选中心 + 范围/过渡滑条」近似单中心色域；图像内点选是可选
  增强（见 §5）。
- **不承诺 1:1 像素复刻**：Adobe 未公开内部公式，公开资料只有 UI 语义 +
  逆向工程近似。工程近似 + 黑盒差分标定（沿用 `ps-color-reduction` 的
  REPORT.md 三轮实验手法）可达到肉眼一致、带内/带外边界行为与 PS 一致。

## 2. PS「色相/饱和度」语义梳理（规格来源见 §6）

界面自下而上（图略，见参考教程）：

- **编辑目标下拉**：「全图」（Master）+ 六个预设色域 红/黄/绿/青/蓝/洋红——
  中心色相 0°/60°/120°/180°/240°/300°（色相环六等分）；现代版还有
  「色相范围标记器」可任意拖动/反选色域。
- **两条色条之间的范围控制（4 个滑块）**：上色条 = 调整前 360° 色相环，下色条
  = 调整后；两内滑块之间为**中心色域**（100% 生效），内滑块与外三角滑块之间为
  **过渡衰减区**（部分生效），外三角之外 **0% 生效**。
  - 红色通道默认数值（多个教程一致）：中心色域 345°–15°（绕 0° 中心 ±15° 全量）；
    过渡区 315°–345° 与 15°–45°（各 30° 宽，线性衰减）——即**内半宽 15°、
    外半宽 45°**（过渡带宽 30°）。
- **三个调整滑块**：色相 −180..+180（正 = 色轮顺时针旋转度数）、饱和度
  −100..100、明度 −100..100。选「全图」时作用于全部有色像素；选预设/自定义
  色域时只作用于该色域（按上面的衰减权重）。
- **三支吸管**：取样 = 把中心色域移到点击处颜色；添加到取样 / 从取样减去 =
  把采样色**合入/剔出**当前色域（加减可让色域变成多段/多峰）。
- **着色（Colorize）**：把作用范围内的像素整体转为「指定色相 + 饱和度 + 明度」
  的单色系（另类语义，不是换色）。
- 经验规则：灰度像素（饱和度 0）与黑/白不受色相/饱和度调整影响（饱和度 0 时
  色相无定义——HSL 模型自然满足）；明度拉到 ±100 分别趋向黑/白。

## 3. 复刻算法（候选实现）

### 3.1 权重蒙版（核心）

对每像素色相 h（度），目标中心色相 c、内半宽 r_in、外半宽 r_out：

```
d   = min(|h − c|, 360 − |h − c|)      # 环上最短距离，0..180
w   = 1                                 # d ≤ r_in（PS 中心色域）
    = (r_out − d) / (r_out − r_in)      # r_in < d < r_out（PS 过渡衰减区）
    = 0                                 # d ≥ r_out（PS 色域外）
```

过渡曲线 PS 未公开：线性已够初版；如需更柔可换 smoothstep（Lightroom/Capture
One 类软件用 smoothstep，见 DSP.SE #86057）；**真实曲线留给差分标定轮**。

实现位置：复用 `color_key_tolerance_sequence` 的逐帧 numpy 形态——
`np.asarray(rgba) → RGB→HSL 浮点 → 算 d/w → 调整 → 转回 RGB`，Alpha 原样
保留（与 adjust_color 族同约定：只动 RGB）。8-worker 并行出口不变。

### 3.2 色空间与调整公式

- **色相**：`h' = (h + hue_shift × w) mod 360`（色相滑块是旋转量）。
- **饱和度 / 明度**：公开逆向（Stack Overflow #4404507，Roman Starkov，存档
  2026-07-26）给出的近似是「重建色」式：目标色 =（灰 ↔ 全饱和目标色相）按
  饱和度插值，再按明度把原亮度向黑/白混合（`L>0 向白`、`L<0 向黑`，比例随
  |ΔL|·(1−L) 之类），转换回 RGB 时保持原亮度关系。注意点：
  - 评论区（Ivan Kuckir）实测「结果偏亮，去掉 ×2 系数更准」——公开逆向的
    系数本身在迭代修正，**不能当权威**；
  - 评论区还指出「选区（非 Master）模式下明度行为完全不同、更像饱和度」——
    公开逆向只覆盖 Master；选区级公式须自标定；
  - dsp.SE #86057：HSL 非感知均匀，跨色相插值可能有伪影（该帖作者换 LCh 解决）。
    本项目处理的是 GIF/动画像素帧，带内 H 偏移路径用 RGB→HSL 往返一般够用；
    是否上 LCh/OKLCH 是视觉质量选项，不是可行性门槛。
- 结论：工程近似公式**足以开工**，精确曲线（饱和/明度的映射形状、过渡衰减
  形状）用差分法标定，不必先花时间追求一次性到位。

### 3.3 与现有节点关系（落地后现状：决策 #134）

落地时发现「色相调整」与新节点「全图」作用域**完全重合**（均为全图色相旋转
−180..180）→ 已物理删除「色相调整」（`adjust_color` 的 hue 分支一并移除），
旧存档 hue 节点经 session 节点类型迁移自动改写为新节点（色域=全图、色相=原值）。
「亮度调整/饱和度调整」保留——它们走 PIL ImageEnhance（亮度≈曝光乘 RGB、
饱和度≈ImageEnhance.Color），与新节点 PS 式「明度（向黑白混合）/饱和度」
公式不同。归属分类：
`NodeCategory.PROCESS` =「画面处理」（决策 #132 重划后：逐帧变换、帧数不变、
无跨帧关系——正是本语义）。

## 4. 落地设计（决策 #134 已按此落地）

落地与草案的差异（均经用户拍板，详见决策 #134）：入口形态 = **单下拉一体**
（草案先讨论了「勾选框+下拉」，信息结构上是「一个下拉 + 冗余开关」，有非法
组合/禁用态/取色器入口问题 → 弃用）；作用范围含「全图」且**默认全图**
（删除「色相调整」后由本节点全图承接，迁移存档语义等价）；「色相/饱和度」
标题；范围/过渡为 FloatParam（非 IntParam）。

- **后端**：`media/backend_color.py` 新纯函数
  `hue_sat_range_sequence(workspace, progress, artifact, *, target_color,
  mode, hue_delta, sat_delta, light_delta, range_half, feather_half)`；
  经 MediaBackend 转发（决策 #120 形态）；测试照 `test_color_key_node.py`
  先例（小图 + execute + 像素断言，不弹 UI）。
- **节点参数表建议**：

  | 参数 | 控件 | 范围 / 默认 | 对应 PS |
  |---|---|---|---|
  | 目标颜色 | ColorParam 色块（取色器） | `#000000` | 吸管取样中心色 |
  | 编辑范围 | ChoiceParam（全图 / 目标色范围） | 全图 | 「编辑」下拉 Master/色域 |
  | 色相 | 滑条+数值框 | −180..180 / 0 | 色相滑块 |
  | 饱和度 | 滑条+数值框 | −100..100 / 0 | 饱和度滑块 |
  | 明度 | 滑条+数值框 | −100..100 / 0 | 明度滑块 |
  | 范围（内半宽） | IntParam 滑条 | 0..180 / 15 | 中心色域（PS 红默认 ±15°） |
  | 过渡（羽化半宽） | IntParam 滑条 | 0..180 / 30 | 外衰减区（PS 红默认 30°） |

  「全图」时蒙版恒 1（忽略目标色/范围），行为与现有全图节点一致但公式不同
  （可用作 A/B 对照）。
- **坑位备忘**（从既有决策带过来的约束）：
  - ColorParam **不要**用 `enabled_when` 置灰（决策 #125：色块恒可用，「启用」
    勾选只控制 execute 是否传参；同理此处「编辑范围=全图」时目标色置灰需求
    若做，也须只对非 ColorParam 控件生效或干脆全显示）；
  - 参数名避 NodeGraphQt 保留字 width/height（先例：out_width/#124、img_width）；
  - 新增节点走既有配方：后端 → backend.py 转发 → 节点类 → registry 注册 →
    docs/node-list.md 表头/首段计数 → 测试 → 决策记录（本次为原位替换
    hue → hue_sat，总数保持 53、画面处理 17 不变）；
  - AST 审计脚本复查 execute 类体声明 + docstring 三行自述。
- **验证路径**：色相渐变测试图（HSL 全环）→ 同参数 PS 输出对照，标定
  饱和/明度映射与衰减形状；比对目标「带内全量、带外零影响」边界（红/蓝交界
  处颜色断裂检查）。测试素材可仿 `scripts/make_gifski_like_gif.py` 的手工
  构造手法写一个生成器。

## 5. 范围外 / 后续可选增强

- 预览/画布图像内**点选取色**（真吸管交互）与加/减采样多段色域（落地版用
  ColorParam 色块定中心，单中心色域）；
- 着色（Colorize）模式；色域取反；
- LCh/OKLCH 高质量跨色相过渡（若渐变素材上发现色带伪影再上）。
