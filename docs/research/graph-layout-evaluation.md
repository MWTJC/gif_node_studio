# 智能布局研究存档（2026-08，整体标记失败/回退）

> 结论先行：为 node 编辑器引入「Sugiyama 式分层智能布局」的尝试**失败**。
> 几何指标全面改善（近方形/零重叠/跨级边大减），但用户实测判定「背景框内
> 节点排布与背景框间排列均令人费解，上游背景框被放到其他背景框右边」。
> 本文固化算法设计、实测数据、败因与未来方向，供后续重启参考。
> 对应决策：[#108（已回退）](../decisions/101-110.md#d108)。

---

## 1. 背景与目标

- 现状：NodeGraphQt 内建 `auto_layout_nodes`（「上游/下游自动布局」）是
  **纯线性排布**——BFS 深度排名后同 rank 节点在单列/单行堆叠，无层内排序、
  无交叉最小化、无节点尺寸参与遮挡规避、多连通分量混排。多输入节点
  （序列相加/叠加、RGBA 通道合并、ico 合成 6 输入）的所有上游源堆成一列。
- 用户需求：自动排布**考虑节点面板实际尺寸、整体趋向方形、互不遮挡、
  间距紧凑**。
- 约束：项目惯例 = 零新增依赖、进程内、可单测（纯计算与 Qt 解耦）。

## 2. 已实现的算法（`core/graph_layout.py`，纯计算无 Qt）

`GraphNode(id, width, height)` + `layout_graph(nodes, edges, ...) → {id: (x, y)}`
（左上角坐标）。Sugiyama 框架简化版 + 三轮针对性改进：

### 2.1 基础（v1）
1. **连通分量**（并查集），分量间沿副轴堆叠、主轴居中；
2. 每分量 **longest-path 分层**（拓扑序 DP，源点层 0；环仅兜底忽略）；
3. **方形化层合并**：层数 > 目标列数 T 时贪心合并相邻稀疏层（节点数之和
   最小者优先，先吞稀疏中间层 → 同层边最少）；
4. **barycenter 层内排序**（相邻层邻居位置均值，同层边不参与，固定轮数 +
   Python 稳定排序 → **确定性**：同输入两次结果逐坐标一致）；
5. **坐标分配**：列宽 = 该列最宽节点，列内按节点高度 + `v_gap` 堆叠、整列
   垂直居中，列间距 `h_gap`；
6. **高长条自适应**：整体高 > 宽时在 `[h_gap, max_h_gap]` 内放大列间距逼近
   方形。

### 2.2 改进 A：源节点就近下放（`_longest_path_layers`）
- 问题：标准 longest-path 把所有入度 0 节点放层 0——「大量独立输入汇聚」
  图（logo 预设 19 个输入源）全部堆第一列 → 9700px 极端高长条 + 21 条
  跨级长边（源在层 0、目标分散在层 2-6）。
- 改法：每个源下放到「其直接下游目标的最小层 - 1」，输入源靠近消费者
  （与手工排布直觉一致）；孤立源保持层 0。去空层后重建层索引。
- 实测：跨级边 21 → 3 条，第一列 19 → 4 个。

### 2.3 改进 B：目标列数按节点尺寸比例（`_squarify_layers`）
- 问题：T = round(sqrt(N)) 未考虑节点尺寸。本项目节点高≈450、宽≈300
  （高>宽），T=7 偏小 → 列内堆叠过高（logo 中央列 10 个 → 5234px 高）。
- 改法：T = round(sqrt(N · avg_h / avg_w))——由「列宽 ≈ T·W、列高 ≈
  (N/T)·H 相等」解出。测试节点 180×90（宽>高）→ T 变小。

### 2.4 改进 C：列拆分（`_split_oversized_columns`）
- 问题：源下放/层合并聚集的列仍过高（logo 中央列 10 个）。
- 改法：每列上限 = ceil(N/T)（与方形化目标联动，链类图不拆）；按**原始层
  边界**贪心切段（切点只落在层交界）——按节点数硬切会把某层节点切开、
  其下游留在原列，产生**反向边**（实测链 10 的 n4 被切到新列后指向左侧
  n5）；切分前须**按原始层号排序段**（切分前的 barycenter 会把低层节点移到
  列尾）。切出的同层边再经一轮 barycenter 对齐。

### 2.5 改进 D：背景框防交叠（`ui/hotkeys/hotkey_functions.py` `_reposition_backdrops`）
- 问题：布局后 backdrop 按组内节点包围盒重包，大矩形互相穿透（分组语义
  混乱）。
- 改法：按组大小降序放置；与已放置背景框交叠时**整组块（背景框 + 组内
  节点）平移**——优先右移（不增加整体高度）、受阻时下移；方向动态按已放置
  区域宽高比选择（高>宽 → 右移）；设位移上限（超出接受轻微交叠）；每次
  只移单方向（**组合位移漏检对角碰撞**，实测节点重叠）；`clear_dy/dx`
  碰撞避让须**强制前进**（dy 至少 +24，避免碰撞节点在下方时 dy 不变死循环）。

### 2.6 UI 接线
- 动作 `node.layout.smart`（智能布局，Ctrl+Shift+L，mdi.auto-fix），画布
  右键菜单 + 菜单栏「节点」组；
- 作用域：选中 ≥2 节点 → 布局选中集；否则全图（只选中 1 个时布局无意义
  = 移到原点，且 `connect_to` 会意外选中目标节点——实测「布局只动 1 个」
  的坑）；
- 背景框布局前记录内含节点（`backdrop.nodes()` 按位置判定），布局后重包；
- 整体包 `begin_undo("智能布局")` 单撤销宏（一次 Ctrl+Z 恢复）。

## 3. 实测数据（logo.json：50 Studio 节点 + 6 背景框 + 59 边）

| 指标 | 手排（用户） | 智能 v1 | 智能最终 |
|---|---|---|---|
| 整体尺寸 | 4743×6457 | 3188×9700 | 6176×5307 |
| 节点重叠 | 2 处 | 0 | 0 |
| 跨级边（列差>1） | — | 21 | ~25（列差≤4） |
| 背景框交叠 | 无 | 有 | 基本无（右下小框轻微残留） |
| 目检评价 | 分组清晰、连线杂乱 | 高长条、框乱 | 近方形、框清晰、连线可读 |

几何指标全绿，vision 目检甚至评价「相比手排更直观」——但**用户实测判定
失败**。几何优化 ≠ 语义直观。

## 4. 失败判定与败因分析（用户反馈）

用户反馈原文：「背景框内的节点排布有点令人费解，且背景框之间的排列也
令人费解，有些处于上游的背景框被放置在了其他背景框右边」。

败因归纳（按严重度）：

1. **背景框防交叠的组块平移破坏拓扑方向（最严重）**：`_reposition_backdrops`
   把整组块右移避让，**上游背景框可能被推到下游背景框右侧**——视觉上
   「上游在右边」，数据流方向感完全错乱。任何后处理平移都必须保持
   「上游在左/上」的拓扑方向，否则宁可接受背景框交叠。
2. **方形化/列拆分与 backdrop 分组语义冲突**：backdrop 是用户语义划分
   （输入源/像素化/放大/gif/ico 各阶段）。全局方形化把组内节点拆散到
   多列、列拆分把同一逻辑阶段（如所有「分辨率统一」）切成多列 → 背景框
   内节点排布失去阶段感，令人费解。
3. **源就近下放的双刃剑**：输入源靠近消费者（单点直观），但多个源被
   分散到不同列后，与「输入源是一组」的分组语义冲突。
4. **局部指标改善 ≠ 整体直观**：无重叠/近方形/跨级边少是客观几何指标；
   用户感受是整体结构（方向、分组、阶段）是否可读。布局算法的第一
   优先级应是**语义保真**（保持分组块状结构与方向感），几何优化其次。
5. **复杂图（50 节点多并行链）无完美解**：手排本身也有 2 处重叠 + 连线
   杂乱，但用户可接受——因为**分组块状结构清晰**。算法若牺牲分组保真，
   几何再好也失败。

## 5. 可复用的经验（正面）

- **纯计算与 Qt 解耦 + 确定性**（固定轮数 + 稳定排序）使布局可单测、
  可 offscreen 冒烟、可渲染 PNG 目检——这套验证流程有效。
- **源就近下放**（跨级边 21→3）与**按尺寸比例定列数**（T = sqrt(N·avg_h/
  avg_w)）在「忽略分组」前提下是对的，可保留为节点布局子模块。
- **列拆分必须按原始层边界**、**切分前按层号排序段**、**单方向避让**、
  **避让强制前进**——这几个坑的修法在 2.4/2.5 已固化。
- **backdrop 内节点**（`backdrop.nodes()`）按位置判定，布局前必须记录
  快照；`connect_to` 会选中目标节点，作用域判定要防「只动 1 个」。

## 6. 未来方向（若重启智能布局）

1. **分组块状布局**：以 backdrop 组为单元——先组内布局（迷你 Sugiyama），
   再以组为超节点做组级布局（组间保持拓扑方向，上游组绝不右移越过下游
   组），最后展开。组内聚 + 组间方向保真，才是用户要的「直观」。
2. **或：布局完全忽略 backdrop**（节点纯拓扑布局），backdrop 仅重包标注，
   接受大框（不做平移避让）——代价是分组框大，但方向感不破坏。
3. **方向硬约束**：任何布局后处理（平移/避让）不得让上游 x 超过下游 x
   （水平方向），违者弃用该优化。
4. **回归对照**：每次改动用 logo.json 加载 → 布局 → 渲染 PNG 目检 +
   人工确认，勿只信几何断言。

## 7. 现状与代码归属

- `src/gif_node_studio/core/graph_layout.py`（纯计算）、
  `ui/hotkeys/hotkey_functions.py` 的 `layout_graph_smart`/`_reposition_backdrops`、
  `ui/actions.py` 的 `node.layout.smart`、`tests/test_graph_layout.py`（15 项，
  含 logo 场景回归）。
- **整体判定失败**：用户自行善后（可能回退代码）。测试契约（确定性/无重叠/
  方向/方形）对纯计算层仍成立；若回退 UI 接线，`core/graph_layout.py` 可
  作为独立模块保留或一并删除，由用户决定。
